# 파싱 설계 v3

> 2026-07-31 · 멘토 피드백(학습 중심 회귀 · 참고서 비유 · 프리로드 · 커뮤니티) 반영
> [DESIGN_v2.md](./DESIGN_v2.md) 4장을 대체한다.

---

## 0. 한 장 요약

**파싱은 자료 하나를 "나만의 참고서 한 권"으로 만드는 일이다.**

```
자료 1개  →  목차 + 조각(원문) + 개념 + 선후관계 + 밀도
```

- **자료 하나씩 독립적으로** 처리한다. 다른 자료를 보지 않는다.
- 합치는 것은 파싱이 아니라 **과목 조립**의 일이다.
- 파싱은 역할(뼈대/본문)을 모른 채 **둘 다 뽑아둔다.**

---

## 1. 3층 구조 — 무엇이 누구 것인가

| 층 | 무엇 | 누구 것 | 언제 만드나 |
| --- | --- | --- | --- |
| **1. 문서** | 목차 · 조각 · 개념 · 선후관계 · 밀도 | **문서** (공용) | 문서당 **한 번** |
| **2. 과목** | 통합 목차 · 자료 조합 · 부족분 채움 | 자료 조합 | 과목 만들 때 한 번 |
| **3. 사람** | 이해도 · 진도 · 북마크 · 재출제 큐 | 사람 | 계속 갱신 |

**파싱은 1층만 만든다.** 2층은 과목 조립, 3층은 학습 엔진.

### 왜 1층이 공용이어야 하는가

지금 코드는 `사용자 → 문서 → 코스 → 개념` 이라 문서가 사용자에 매달려 있다. 그래서:

- 같은 교재를 두 명이 올리면 **두 번 파싱**한다
- EBS·스탠포드 교과서를 **미리 올려둘 자리가 없다**
- 남의 내용을 **가져다 쓸 수 없다**

바꾸면:

```
문서(공용) → 조각 · 개념              ← 1층
과목 = 문서 조합 → 통합 목차           ← 2층
사용자 → 수강 → 학습 상태              ← 3층
```

이러면 **프리로드 · 커뮤니티 공유 · 내용만 재생성**이 전부 열린다.

> **소유 구조 변경은 나중에 하면 마이그레이션이 크다. 제일 먼저 정해야 한다.**

## 2. 자료의 역할 — 뼈대 / 본문 / 경향

### 뼈대는 역할이 아니라 기본값

**사용자가 올린 자료 = 내가 배울 범위.** 그러니 무조건 뼈대다.
**본문은 겸할 수도, 못 할 수도 있다.** 밀도가 정한다.

| | 뼈대 (범위) | 본문 (내용) | 경향 (출제 신호) |
| --- | --- | --- | --- |
| 누가 | **항상 내 자료** | 밀도 충분하면 내 자료, 아니면 프리로드 | 기출·문제집만 |
| 정하는 것 | 목차 · 무엇을 배울지 | 설명 · 문제 재료 · 근거 | 비중 · 난이도 · 유형 |

### 케이스

| 조합 | 뼈대 | 본문 | 경향 |
| --- | --- | --- | --- |
| 교재 한 권 | 교재 | 교재 (자급자족) | — |
| **PPT만** | PPT | **프리로드에서 전부** | — |
| **PPT + 교재** | **PPT** | 교재 (+ 부족분 프리로드) | — |
| PPT + 교재 + 기출 | PPT | 교재 | 기출 |
| 논문 | 논문 | **프리로드** (배경 설명) | — |

### 목차 우선순위 — PPT가 이긴다

교재도 PPT도 목차가 있을 때:

1. 사용자가 지정한 **주 자료**
2. 없으면 **PPT · 강의계획서** (교수님이 정한 게 시험 범위)
3. 그것도 없으면 첫 번째 자료

교수님이 교재 15장 중 7장만 다루면, 나머지 8장은 안 쓴다.

### "나만의 참고서"의 실체

프리로드에서 당겨온다고 **프리로드의 목차를 쓰는 게 아니다.**

```
📘 2. 스케줄링          ← 내 수업 목차 (PPT 기준)
   ├ 📊 슬라이드 13~20   (교수님)
   ├ 📕 교재 5장         (설명)
   └ 📚 표준 교재 3.2절  (교재에도 없던 부분)
```

**목차는 내 수업, 내용은 여러 데서.** 이게 참고서다.

## 3. 파이프라인

```
[입력 어댑터]  형식별 ─────────────────────────
   PDF · PPTX · DOCX · 이미지  →  Document Parse
   웹 · 위키 링크              →  HTML fetch
   (녹음)                      →  STT — 범위 밖
                    ↓
            [ 요소 배열 ]  ← 여기부터 형식 무관
                    ↓
[공통 파싱] ──────────────────────────────────
   ① 정제        표지·목차·저작권·페이지번호 딱지 (삭제 아님)
   ② 조각 만들기  요소 묶음. 표·수식 안 쪼갬. 문장 분리 + 앵커
   ③ 목차 만들기  조각을 10개 이내 주제로 분류. 조각 수 보존 검산
   ④ 개념 추출    조각마다 개념 + 선후관계
   ⑤ 개념 정리    문서 안 중복 합침, 주소는 누적
   ⑥ 전역 키 연결 전역 개념 사전에 붙임
   ⑦ 밀도 측정    본문으로 쓸 만한가
                    ↓
[역할 분기] ──────────────────────────────────
   본문  → 조각·개념 전부 살림
   뼈대  → 목차·개념만 씀, 설명은 프리로드
   경향  → 문항 분해 → 개념 태깅 → 출제 프로파일
```

**형식이 늘어나면 어댑터만 추가한다. 나머지는 안 건드린다.**

### 핵심 알고리즘 3개

**① 조각 → 목차 분류**
- 자료에 목차가 있으면 그 항목을 라벨 후보로, 없으면 10개 이내 주제를 생성
- **원문을 자르거나 고치지 않고 라벨만 붙인다** → 조각 수가 보존되어 누락이 산술적으로 검증됨
- 기존 방식(LLM이 장 경계 판정 + 가드레일 5개)을 **통째로 대체**한다

**② 개념 정리 — 주소 누적**
- 이름 정규화 → 임베딩 유사도 → 애매하면 LLM 판정 (기존 3중 방식 유지)
- **병합할 때 출처를 버리지 않고 합친다** ← 기존 코드의 결함
- 결과: 개념 1개가 조각 여러 개를 가리킴

**③ 밀도 측정**
- 조각당 평균 글자수 · 개념당 원문량 · 커버리지
- → 본문으로 쓸지, 뼈대로만 쓸지 자동 제안 (사용자가 변경 가능)

## 4. 산출물 스펙 — 5덩어리

**이것만 있으면 파싱을 다시 안 해도 된다.**

### ① 문서 메타

```
문서 ID · 파일명 · 형식 · 총 페이지 · 총 조각 수
지문(해시)      ← 같은 자료 중복 파싱 방지
파싱 버전       ← 파서 개선 시 재파싱 대상 선별
공개 범위       ← 개인 / 공용(프리로드)
```

### ② 원문 조각 — 읽기·생성·검증의 재료

| 필드 | 왜 필요 |
| --- | --- |
| 순서 번호 | 원문 흐름 유지 |
| **소속 목차 ID** | 목차 아래 모으기 |
| **마크다운 본문** | 화면에 그대로 렌더 (표·수식 포함) |
| **문장 배열 + 문장별 앵커 ID** | 북마크 · 드래그 · 근거 표시 |
| 그림 참조 (인라인 위치) | 원문 흐름에 그림 복원 |
| 페이지 범위 · 요소 범위 | "교재 33p" 표시 |
| 임베딩 | 검색 · 유사도 |

**조각은 자를 뿐 고치지 않는다.** 파서가 글자를 바꾸면 원문 대조 검증이 성립하지 않는다.

### ③ 목차 — 진도·집계의 단위

```
순서 · 제목
소속 조각 ID 목록    ← 원문이 여기 다 들어있음
소속 개념 ID 목록    ← 이해도를 여기서 집계
페이지 범위
자료별 범위          ← "교재 31~38p / 슬라이드 19~24"
```

### ④ 개념 — 이해도·진단의 단위

| 필드 | 왜 필요 |
| --- | --- |
| 이름 · 한 줄 정의 | 표시 |
| **전역 키** | 과목 넘어 연결 · 프리로드 매칭 |
| 소속 목차 ID (**1개**) | 이해도 집계 지점 |
| **원문 주소 여러 개** (조각 ID + 문장 앵커) | 이 개념의 원문 **전부** |
| **선후관계** (다른 개념 ID) | 오답 원인 진단 |
| 자료 출처 표시 | "슬라이드에만 있음" 배지 |

**개념 하나를 집으면 그 개념의 원문이 전부 딸려 나와야 한다.** 그래야 설명 재생성 · 문제 생성 · 근거 표시가 다 된다.

### ⑤ 그림

```
이미지 · 소속 조각 · 인라인 위치 · 캡션 · 페이지
```

### + 품질 지표

```
밀도 등급           본문 가능 / 뼈대만
조각당 평균 글자수
커버리지            개념이 붙은 조각 / 총 조각
미분류 조각 목록
목차별 조각·개념 수
```

## 5. 지켜야 할 규칙 4개

1. **모든 조각은 정확히 하나의 목차에 속한다** — 조각 42개 → 목차별 합계 42개. 안 맞으면 파싱 실패
2. **모든 개념은 최소 1개의 원문 주소를 갖는다** — 주소 없는 개념은 지어낸 개념
3. **원문은 수정되지 않는다** — 자르고 분류할 뿐, 글자를 바꾸지 않는다
4. **여기엔 사람 것이 하나도 없다** — 설명 블록 · 문항 · 이해도 · 진도 · 북마크는 전부 밖

### 관계 정리

| 관계 | 개수 |
| --- | --- |
| 조각 → 목차 | **1** |
| 목차 → 조각 | 여러 개 |
| 개념 → 소속 목차 | **1** (집계 지점) |
| 개념 → 원문 주소 | **여러 개** (재료) |
| 조각 → 개념 | 여러 개 |

**개념 ↔ 조각만 다대다, 나머지는 1대다.**

### 개념에 원문이 여러 개인 이유

**① 자료가 달라서** (제일 큼) — 교재 36p + 슬라이드 21 + 프리로드 3.2절
**② 같은 자료 안에서 나눠 설명** — 정의는 6p, 단계는 11p
**③ 뒤에서 다시 나옴** — 재귀가 2장(정의)과 9장(응용)에

③은 목차를 넘으므로 **소속 목차는 1개(2장), 원문 주소는 2개**로 처리한다.

## 6. 형식별 처리

| 형식 | 어댑터 | 구조 | 밀도 | 기본 역할 | 조각 경계 |
| --- | --- | --- | --- | --- | --- |
| 교재 PDF | Document Parse | 제목 계층 ◎ | 높음 | **본문** | 제목 |
| 위키 · 기술문서 | HTML fetch | 헤딩 ◎ | 높음 | **본문** | 헤딩 |
| 논문 PDF | Document Parse | 섹션 ○ | 중간 (설명 없음) | 본문 (읽기 위주) | 섹션 |
| **PPT / PPTX** | Document Parse | 슬라이드 ○ | **낮음** | **뼈대** | **슬라이드** |
| 스캔 이미지 | Document Parse (OCR) | 없음 | 중간 | 본문 | 문단 |
| DOCX | Document Parse | 제목 계층 ○ | 높음 | 본문 | 제목 |
| **기출 PDF** | Document Parse | 문항 번호 | — | **경향** | **문항** |
| 녹음 | STT (범위 밖) | 없음 | 낮음 (구어체) | 뼈대 (약함) | 시간·주제 |

**형식별 특이 처리**
- **PPT** — 슬라이드 경계가 이미 조각 경계. 발표자 노트도 캐냄
- **논문** — 참고문헌 · 저자정보 제거
- **웹** — 네비게이션 · 광고 제거
- **스캔** — 구조 정보가 없어 밀도를 낮게 잡음

### 녹음은 지금 넣지 않는다

- 현재 제약(Solar · EXAONE)에 음성인식이 없다
- STT를 붙여도 문단·제목 경계가 없고 구어체라 파싱이 어렵다
- 판서·화면을 말로만 가리켜("여기 보시면") 맥락이 소실된다
- 멘토 피드백에서도 녹음은 **지원 대상이 아니라 페인포인트 예시**로 나왔다 ("녹음해두고 다시 안 듣는다")

## 7. 기출 — 문항이 아니라 신호다

**기출을 문제은행에 넣지 않는다.**

- **저작권** — 원문 재배포 없음 원칙과 충돌
- **정체성** — 우리는 문제를 *만드는* 서비스지 기출 유통이 아니다
- **학습 효과** — 기출을 그대로 풀면 답을 외운다

### 산출물 = 출제 프로파일

```
개념별 출제 빈도    LRU 3년 연속 / 워킹셋 5년간 0회  → 출제 비중
난이도 분포         이 과목 기출은 난이도 3~4에 몰림  → 생성 난이도 기준
문항 유형 분포      계산형 60% · 개념형 30%          → 생성 유형 비율
범위 확인           기출에 없는 목차                 → 우선순위 하향
```

### 문항 원본

**저장하되 출제하지 않는다.**
- 개인 자료로만 (공용 자산 아님, 공유 안 함)
- "3년 연속 출제" 옆에 본인만 원본 열람
- 생성 시 문체·형식 참고로만 사용

> 발표 문구: **"기출을 베끼지 않습니다. 경향만 읽습니다."**

## 8. 기존 코드 대비 차이

### 이미 있는 것 (그대로 씀)

- Document Parse 호출 (요소 + 그림 크롭까지)
- 정제 (규칙 + LLM 스캔, 삭제 아닌 마킹)
- **원문 마크다운** — `doc_chunks.content`에 표·수식 포함해 저장됨
- **그림** — `doc_figures`에 이미지 + `element_id` 위치
- **요소/페이지 범위** — `element_from/to`, `page_from/to`
- **개념 추출 + 선후관계** — `concept_edges`에 저장됨
- 임베딩 (청크·개념)

### 바꾸는 것 8개

| # | 기존 | 새로 | 크기 |
| --- | --- | --- | --- |
| 1 | 문서가 **사용자 소유** | **공용 자산** | **구조 변경** |
| 2 | 개념이 **코스 안에 갇힘** | **전역 개념 사전** | **구조 변경** |
| 3 | 목차 = LLM이 장 경계 판정 (가드레일 5개, 실패 시 파일명 1개로 퇴화) | **조각을 주제로 분류.** 조각 수 보존 검산 | 중 |
| 4 | 개념당 출처 **1개** (`source_chunk_id` 단수) | **다대다** | 중 |
| 5 | 중복 병합 시 **출처 버림** (엣지만 이관) | **출처 합침** | 소 |
| 6 | 좌표가 **페이지·요소** 단위 | **문장** 단위 앵커 | 소 |
| 7 | 커버리지·밀도 확인 **없음** | 조각 수 대조 + 밀도 등급 | 소 |
| 8 | 그림이 본문에서 **분리** | 원문 흐름에 **인라인 복원** | 소 |

**4·5는 이미 손에 들고 있던 정보를 버리는 것이라 추가 비용 0으로 고칠 수 있다.**

## 9. 작업 순서

**1순위 — 소유 구조** (#1)
파싱 결과가 개인 것이냐 공용 자산이냐. 나중에 바꾸면 마이그레이션이 크다.
→ **공용으로 간다.** 프리로드도 커뮤니티도 여기서 나온다.

**2순위 — 목차 분류 + 다대다** (#3 #4 #5)
파이프라인의 본체. 장 경계 판정을 대체하고 주소를 누적한다.

**3순위 — 읽히는 형태** (#6 #8)
문장 앵커 + 그림 인라인. 태블릿 학습 UI가 여기에 의존한다.

**4순위 — 밀도·커버리지** (#7)
프리로드를 언제 당길지 결정하는 스위치.

**5순위 — 전역 개념 사전** (#2)
과목 간 연결 · 프리로드 매칭. 코스가 여러 개 쌓여야 의미가 생긴다.

### 지금 안 해도 되는 것

- 닫힘/열림 판정 — 문제은행이 메인이 아니게 됨
- 사슬형/나열형 판정 — 동일
- 녹음 STT — 범위 밖
