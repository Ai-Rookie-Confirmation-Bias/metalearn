## 1. 한 줄 정의

**강의 PDF를 올리면 AI가 개념 그래프로 구조화해 나만의 커리큘럼을 만들고, "설명해주는" 대신 "꺼내게 하는"(인출) 방식으로 학습시키며, 학습 상태를 개념 단위로 기억해 커리큘럼이 학습자를 따라 계속 재구성되는 1:1 메타인지 튜터.**

발표용 서사: *"수준 맞춤을 1회성 시험에서 학습 행위 전체로 확장했다 — 학습자의 상태가 곧 커리큘럼."*

## 2. 제안서 대비 무엇이 어떻게 진화했나

> 방향: 제안서에서 **이탈한 게 아니라 심화**했다. 제안서의 문장을 더 문자 그대로 구현하는 쪽으로.

| 제안서(2026-05) | 현행 | 진화 이유 |
|---|---|---|
| 진단 테스트·사전 퀴즈로 수준·취약 파악 → 로드맵 | **배치고사 최소화(5~12문항, floor 출발점만)** + 이후 인출이 상시 평가 | 시험 반복=스트레스, 오채점 1개에 무너지는 브리틀함(실측). "학습자의 상태가 곧 커리큘럼"은 스냅샷이 아니라 상시 갱신이어야 함 |
| (없던 개념) | **성향 진단** — 로그인 직후 계정 1회, 3문항 샘플 선택형(비유/원리/맥락 설명 중 선택), 스킵 가능 *(※ 사전 프로브 채택은 회의 최종 확정 대기 — 07_09 §6)* | 회의 결정. 단, 성향은 **표현에만** 반영(내용·양·순서 불변) — "성향으로 커리큘럼 맞춤"이라고 말하지 않는다. 주 기능은 어디까지나 수준·취약 기반이며, 여기서 **수준 맞춤 = 진입점·개입·복습(구조)이지 콘텐츠 내용이 아니다**(풀컨텍스트 원칙과 모순 없음) |
| 인터랙티브 **학습 캔버스** UI | **지식그래프 시각화 레이어** — conceptMap·chart·timeline·tree·image 블록 (UXUI 카탈로그에 설계·목업 완료, `concept_edges` 스키마 준비) — 🔨 **구현 전** | 강사 피드백 최대 항목("텍스트만으론 학습 UX 붕괴") + 제안서 약속. 봉투+registry 구조라 렌더러 추가만으로 확장 가능 |
| 맞춤 = 학습자에 맞는 커리큘럼 구성 | **내용은 줄이지 않는다(풀컨텍스트)** — 아는 부분은 숨기는 게 아니라 인출 2연속 통과로 **증명하고 빠르게 완료** | 내용 축소는 학습 결손 위험. 스킵의 근거를 "추정"이 아니라 "방금 증명"으로 |
| 막힘 시 개입(연표·비유로 재접근) | **원인별 개입 사다리** — 해설 → 같은 절 보충 → 다음 장 오답노트 weaving → 선행 챕터 삽입(구조적 결손 확정시만, 최후 수단) | 틀린 이유(기초 없음/미소화/망각)가 다른데 처방이 하나면 오히려 역효과. 판정은 BKT×DAG 국소화 알고리즘 |
| 망각 곡선 복습 | SM-2 스케줄 구현·검증 + **오답노트 weaving**(다음 장 시작에 지난 약점 복습 카드) | 복습을 별도 코너가 아니라 다음 학습 안에 짜 넣음(간격 반복+교차 학습) |
| EXAONE 3.5 2.4B 온디바이스 | **EXAONE 4.0 1.2B** (LG 멘토링 권고) + 경계 확정: *미리 만들 수 있는 건 온라인(생성·근거), 실시간 상호작용은 오프라인(채점·꼬리질문)* | 멘토링 검증. 데모 MVP 구동 확인(`feat/ondevice-exaone-mvp`) |
| 단일 자료 업로드 | **다중 PDF → 1코스 통합**(주교재 순서 stacking / 보조자료는 RAG 근거만) + 개념 중복 3단 병합 | 대학 강의는 주차별 PDF 여러 개가 실사용 시나리오 |

**변하지 않은 것(제안서 그대로)**: 인출 중심 능동 학습 / 개념 단위 장기 상태 추적 / 근거(grounding) 기반 생성 / 클라우드+온디바이스 이중 구조 / Upstage Solar + LG EXAONE 국내 AI 풀스택.

## 3. 전체 사용자 플로우

```
[가입/로그인]
   └─ 성향 프로브 (1회·3문항 샘플 선택형·스킵 가능) → users 프로필
      "어떤 설명이 와닿나요?" — 비유형 / 원리형 / 맥락형

[코스 생성]
   └─ 다중 PDF 업로드(주교재/보조자료) → 파싱·정제·청킹·임베딩
      → 개념 추출 → 개념 그래프(원문 청크에 grounding) → 커리큘럼 트리
   └─ 배치고사: 커리큘럼 앞부분 + 선수지식만 가볍게(5~12문항, 무피드백)
      → floor(출발점)만 보수적으로 확정 — 커리큘럼을 자르지 않는다

[학습 루프]
   ├─ 커서 = floor에서 시작, 커리큘럼은 풀컨텍스트로 전부 보임
   ├─ 절 진입 → JIT 생성(티칭 먼저: 정의→원리→예시, 성향 스타일로 표현)
   │   → faithfulness 근거 검증 → 정답 스트립 봉투 서빙
   ├─ 인출(빈칸·객관식·설명하기) → 서버 채점 → 이것이 곧 상시 평가
   │   ├─ 아는 절: 2연속 통과 → 빠른 완료(증명하고 통과)
   │   └─ 오답: 원인 국소화 → 개입 사다리
   │       해설 → 보충 → [다음 장 weaving] → [선행] 챕터 삽입(+복귀 커서)
   └─ 복습: SM-2 망각 시점 도래 + 다음 장 시작 복습 카드

[상태 갱신 — 재진단 없음]
   attempts·concept_mastery 누적 → 수준은 매 인출로,
   성향은 행동 검증으로(비유 스타일에서 실제 성적이 좋은가) 갱신
```

## 4. 맞춤의 구조 — 3레이어 직교 (핵심 설계 원칙)

세 가지 맞춤이 **서로 다른 것만** 바꾼다. 뭉뚱그리지 않는다.

| 레이어 | 바꾸는 것 | 안 바꾸는 것 | 갱신 속도 | 신호 |
|---|---|---|---|---|
| **성향** | 표현(비유·예시 스타일) | 내용·순서·양 | 느림 (1회 + 행동 검증) | 프로브 + 스타일별 인출 성적 |
| **수준** | 시작점·진행 속도(빠른 완료) | 콘텐츠 자체 | 상시 (매 인출) | attempts → BKT |
| **사건** | 구조(선행 삽입·weaving·복습) | 표현 | 사건 발생 시만 | 오답 국소화·망각 도래 |

**변화 가시성 원칙: 커리큘럼은 말없이 변하지 않는다.** 모든 변화에 이유 라벨 — `[선행] 네트워크 — 방금 LAN을 틀렸는데 이 개념이 기반이에요`, `복습 카드 — 5일 전 배운 캡슐화, 잊힐 때가 됐어요`. 불안정감을 메타인지 기능으로 뒤집는 장치이자, "메타인지 튜터"라는 이름의 실체.

**충돌 시 승자 규칙**: 진단과 인출 신호가 충돌하면 **인출이 이긴다** (진단=프라이어, 인출=증거).

## 4.5 학습 캔버스 — 시각화 레이어 (🔨 설계됨 · 구현 전)

> 제안서의 "인터랙티브 학습 캔버스" 약속이자, 에듀테크 강사 피드백 최대 항목("설명이 텍스트뿐")에 대한 답. **아직 구현 전** — 상태를 정직하게 표기한다.

- **무엇**: 텍스트 블록 옆에 시각 블록 — 개념지도(conceptMap, 코스의 개념 DAG를 지도로), 차트(chart), 타임라인(timeline), 트리(tree), 원문 이미지(image).
- **준비된 것**: UXUI 카탈로그(`UXUI_ANT/components.html`)에 전 블록 설계·목업 완료 / 데이터는 이미 있음(`concept_edges` DAG, `chapters·sections` 트리, mastery 상태).
- **작업 범위(정직하게 두 갈래)**:
  - **본문 내 시각 블록**(chart·image·timeline을 절 안에 삽입) = 봉투+registry라 **렌더러 추가만으로**(마이그레이션 0).
  - **코스 개념지도**(conceptMap + mastery 히트맵) = 렌더러만으론 안 됨. **① 커리큘럼 API에 엣지 노출**(현재 트리 API는 엣지 미포함 — 확인됨. 엣지는 `documents` 엔드포인트의 `prerequisite_ids`로 이미 있어 재활용 가능) **② 그래프 렌더링 방식/라이브러리 추가**(현재 프론트에 그래프 lib 없음).
- **왜 중요**: "커리큘럼이 살아 움직인다"(선행 삽입·복습 weaving)를 **눈으로 보여주는 유일한 방법**이 지도다. 텍스트 트리로는 변화가 안 보인다. 개념지도 위에서 mastery가 색으로 차오르고 선행이 끼어드는 장면 = 데모 클라이맥스이자 제품의 얼굴.
- **순서**: 1차 = 학습 트리 시각 개선 + [선행]·복습 이유 라벨(§4 가시성 원칙), 2차 = conceptMap(개념지도 + mastery 히트맵, 엣지 API+렌더러 동반), 3차 = 생성 콘텐츠 내 diagram 블록(LLM이 Mermaid 생성).

## 5. "GPT에 PDF 던지기"와 다른 점 — LLM과 알고리즘의 역할 분리

> 심사 대응 포인트: "LLM이 다 해줬다"가 아니다. **LLM은 콘텐츠 생성만, 판단은 전부 우리 알고리즘.**

| 역할 | 담당 |
|---|---|
| 콘텐츠 생성(티칭·문항·비유) | LLM (Solar / K-EXAONE) |
| 생성물 근거 검증(hallucination 폐기) | faithfulness 게이트 (블록 단위 원문 대조) |
| 채점 | 서버 (정답은 클라이언트에 안 감 — 스트립+치팅 방어) |
| 오답 원인 판정 | BKT × 개념 DAG 국소화 (기초 없음/미소화/망각 구분) |
| 복습 시점 | SM-2 망각 곡선 |
| 진행·잠금·완료·커리큘럼 변화 | 서버 규칙 (이유 라벨과 함께) |
| 학습 상태 | PostgreSQL 영속 (대화 휘발 아님 — 몇 주짜리 학습을 지탱) |

## 6. 온디바이스 트랙 (접근성 차별화)

- **문제의식**: 클라우드 AI 튜터는 안정적 인터넷+구독료 전제 → 정작 1:1 튜터링이 가장 절실한 학습자에게 닿지 않음. + 학습 기록이 기기 밖으로 나가지 않는 프라이버시.
- **경계**(LG 멘토링 2026-07-09 확정): 온라인 = K-EXAONE-236B가 생성·근거 검증 → 검증된 콘텐츠를 기기에 캐싱 / 오프라인 = EXAONE-4.0-1.2B(4bit, llama.cpp)가 채점·힌트·꼬리질문 실시간 수행.
- **상태**: 데모 MVP 구동 확인(업로드→생성→오프라인 인출학습). 남은 것: 채점 신뢰성(골든라벨 벤치+LoRA, ISSUE-020).

### 비용 구조 / BM 한 줄

- **클라우드 경로**: JIT 생성 = 학습자가 진입한 챕터만 그때 생성 → 전체 선생성 대비 절감 (실측 지표화 예정 — "많이 쓸수록 비용 폭증" 우려에 대한 구조적 방어). 챗봇(AI튜터)은 세션/일 캡.
- **온디바이스 경로**: 생성·검증은 온라인에서 1회 → 이후 학습 반복 비용 **0원** (구독료·데이터 요금 없는 1:1 튜터 = 접근성 서사와 BM이 같은 문장).
- 과금 스키마(`plans`·`subscriptions`·`payments`)는 정본 SCHEMA.md에 이미 정의됨 — B2G/B2B2C(교육청·NGO 보급 사업) 우선.
