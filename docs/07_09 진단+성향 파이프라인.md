# 07_09 진단+성향 파이프라인 (결정문)

> **작성**: 2026-07-09 · **성격**: 설계 결정문 (로컬, 팀 공유용 초안)
> **배경**: 제안서("지식 수준 맞춤 커리큘럼") ↔ 현 구현(yoonhs-integration: 배치고사→mastered/locked 축소) ↔ 팀 회의(성향+풀컨텍스트+인출 상시평가)가 서로 어긋나 보이는 문제를 정리.

## 0. 정합성 판정 (왜 이렇게 정리했나)

- 제안서 §1.2의 약속은 "출발점 개인화 + 취약 중심 구성 + **학습자의 상태가 곧 커리큘럼**". 내용 **축소**는 약속한 적 없음.
- "상태가 곧 커리큘럼"을 더 문자 그대로 구현하는 쪽은 **인출 상시평가**(상태가 계속 갱신됨). 1회 진단 확정 방식은 스냅샷일 뿐이고, 실측(07-08/09 E2E)에서 오채점 1개로 floor가 붕괴되는 브리틀함이 확인됨.
- 진짜 이탈 위험은 구현이 아니라 **서사**: "성향 진단으로 맞춤 커리큘럼"이라고 말하는 순간 제안서(수준 맞춤)에서 벗어남. 성향은 표현(비유·예시)에만 국한한다고 항상 명시할 것.

**충돌 시 승자 규칙: 진단과 인출 신호가 충돌하면 인출이 이긴다.** (진단=프라이어, 인출=증거)

## 1. 확정 파이프라인

```
[가입/로그인]
   └─ 성향 프로브 (계정 1회, 3문항 샘플 선택형, 스킵 가능)
      → users 프로필 저장 (갱신 가능한 가설, 고정 라벨 아님)

[코스 생성]
   └─ 다중 PDF 업로드 → ingest → 배치고사(최소: floor 바닥 체크만, 보수적)
      → 커리큘럼 생성 (풀컨텍스트, 축소 없음)

[학습]
   ├─ 커서 = floor에서 시작
   ├─ 아는 절 → 인출 통과 시 "빠른 완료" (콘텐츠 숨김 아님, 인출로 증명하고 통과)
   ├─ 모르는 절 → 티칭(성향 스타일로 표현) + 인출
   ├─ 오답 → 원인별 개입 사다리 (§3)
   └─ 복습 → SM-2 도래 + 오답노트 weaving
```

## 2. 결정 사항

### 2-1. 진단(배치고사) = 바닥 체크만
- floor 산정만 담당. **mastered/locked 확정 라벨 폐지** → mastery **프라이어**(초기 추정치)로 강등. 커리큘럼 구조를 자르지 않는다.
- floor는 **보수적으로**(애매하면 더 앞) — 앞에서 시작하는 비용은 빠른 완료가 흡수, 뒤에서 시작하는 비용(결손 위에 쌓기)은 회수가 느림.
- 근거: 빠른 완료가 있으면 진단 오류 비용이 "몇 분의 지루함"으로 하락 → 진단을 최소화해도 안전.

### 2-2. 인출 = 수준 최신화의 주축
- 각 절의 인출(attempts 서버 채점)이 상시 평가 신호. 별도 재진단 없음.
- **빠른 완료 게이트**: 인출 2연속 통과(streak 규칙, BKT 문턱 아님 — 설명 가능성 우선) 시 절 완료 처리.
  - 스킵의 거짓양성(모르는데 통과)은 이후 국소화→선행 삽입이 안전망 (지연 교정 가능).
  - 거짓음성(아는데 갇힘)은 교정 루트가 없어 이탈로 직결 → 스킵 바를 과도하게 올리지 말 것.
- **BKT 이원화**: 실시간 = 빠른완료 게이트 뒤의 신호 / 사후 = blame(국소화)·복습 우선순위. 커리큘럼 축소에는 사용하지 않음.

### 2-3. 성향 = 로그인 직후 계정 레벨, 표현에만
- 시점: 가입/로그인 직후 (코스 아님 — 과목 독립 속성). **스킵 가능**, 스킵 시 기본 스타일.
- 방식: 자기보고("어떤 형태가 기억에 남나요?") 대신 **샘플 선택형** — 쉬운 개념 하나를 비유형/원리형/맥락형 3버전으로 보여주고 "가장 와닿는 설명" 선택.
- 저장: `users` 성향 프로필 필드 (ISSUE-009 해소). **갱신 가능한 가설** — 이후 인출 성적으로 검증·갱신.
- 반영: 생성 프롬프트의 **스타일 파라미터 1개**로만 (N-변형 생성 아님 → 생성 부하 증가 없음).
- 서사 규율: "성향에 맞추면 학습 효과↑" 주장 금지(학습스타일 신화 공격 노출). "선호 기반 표현 다양화 + 데이터로 검증"으로만.
- 의존성: "로그인 직후" 시점이 필요 → **feat/oauth-login 병합 우선순위 상승** (코드 완성, 자격증명만 남음).

## 3. 개입 사다리 (오답 처방 라우팅)

오답의 원인 3종: ① 구조적 결손(선수 개념 부재) ② 본문 결손(방금 배운 것 미소화) ③ 망각.
**커리큘럼 구조를 바꾸는 개입(선행 삽입)은 ①에만 정당.** 라우팅 판정은 기존 국소화(BKT×DAG)가 담당.

| 단계 | 개입 | 시점 | 대상 원인 | 상태 |
|---|---|---|---|---|
| 1단 | reveal(정답+해설) | 즉시 | 전부 | ✅ 있음 |
| 2단 | supplement(같은 개념 보충 변형) | 같은 절 | ② **본문결손 즉시** | ✅ 있음 (nextAction) |
| 3단 | **오답노트 weaving** — 다음 장 시작에 복습 블록 | 다음 장 | ③ 망각 + ② 중 **2단 소진 후에도 미해결**(에스컬레이션) | ⬜ 신규 |
| 4단 | **선행 챕터 삽입** (구조 변경, 최후 수단) | 즉시 우회 | ① 확정시만 | ✅ 있음, 조건 좁히기 |
| 병행 | SM-2 복습 도래 | 망각 시점 | ③ | ✅ 있음 |

### 4단(선행 삽입) 수정 3건

> **⚠️ 2026-07-09 코드검증 반영(#1 재작성).** 기존 진단 "cause=content인데 nextAction=prerequisite 모순 신호"는 **사실과 다름**. `service.py:588-592`에서 삽입은 `cause.type=="prerequisite"`일 때만 발동(주석 `content면 삽입 안 함`) → content→prereq 삽입 버그는 **존재하지 않음**. 진짜 버그는 아래 #1.

1. **발동 조건 — 진짜 버그는 `P(known)`의 무증거/부정증거 혼동**: `localize():64`가 `weak = [선행 중 p_known < 0.5]`인데, **콜드스타트 선행은 안 풀어봐서 p_known=0.0**(07-09 실측: 정답 응답에도 `P(known)=0.00`). "약함"이 아니라 "안 쟀음"인데 구분을 못 해, 대상 2번 오답 + 미측정 상류 → **선행 오발**. 형식오류 아닌 정상 오답으로도 재현되므로 채점 견고성(422)만으론 안 막힘(아래 ※ 참조).
   - 처방: (a) blame 선행은 `p_known<0.5` **AND `attempts>0`**(실제 증거)인 것만 weak. 무측정/floor 아래는 known prior. (b) `cause`는 **개입에 쓸 때만 계산·노출** — `localize()`가 정답에도 호출(docstring:52)돼 `cause=prerequisite + action=advance + prerequisite=null`을 뱉는 게 화면상 "삽입한다더니 아무 일 없네"의 정체. (c) 발동 = `시도 ≥2 AND cause=prerequisite AND blame이 실제 증거 기반`.
   - ※ 우선순위 1번(채점 견고성)의 userInput 422 거부와는 별개 결함 — 422는 형식 오류 오염을 막고, 이 항목은 **정상 오답**으로도 재현되는 오발을 막는다. 둘 다 필요.
2. **삽입 상한**: 챕터 진행 중 1~2개. 초과분은 오답노트로 강등 → weaving으로 처리 (복습 폭탄 방지).
3. **삽입된 선행에도 빠른 완료 적용**: 인출 통과 시 즉시 복귀 — 거짓 삽입의 비용을 몇 분으로 축소. `[선행]` 배지에 삽입 사유 1줄 표기(방금 X를 틀렸는데 이 개념이 기반) — 메타인지 + 데모 장면.

### 3단(weaving) 구현 규약
- 라우팅: localization 판정으로만 진입 (선행 삽입과 이중 발화 금지 — 구조 결손은 4단, **망각은 3단, 본문결손(②)은 2단 즉시 supplement**). "지금 미소화"를 다음 장으로 미루지 않는다.
- **2단→3단 에스컬레이션**: 단, 2단 supplement를 소진하고도 미해결인 본문결손(절 이탈 시점 mastery 낮음)은 3단으로 승계 — 즉시 보충 + 다음 장 재노출은 중복이 아니라 간격 반복(회의 원안 "인출에서 걸린 것 → 오답노트" 범위 유지). 방치 구간(2단 실패 후 SM-2 도래까지 공백) 제거 목적.
- **⚠️ 선행조건(코드검증 2026-07-09)**: 현재 `localize()`는 망각을 감지 못함 — 입력이 `target_p_known/attempts/prereqs/misconception`뿐이라 **망각(예전 mastered) vs 미학습(첫 대면)을 못 가림**. 3단 라우팅하려면 `localize()`에 **`was_previously_mastered` 입력 신규 필요**(§5 참조). 그 전엔 weaving을 켜지 말 것(미학습에 오발).
- faithfulness: weaving 블록의 근거 집합 = 현재 절 청크 **∪ 원 약점 청크** (게이트를 끄지 않고 근거 범위를 명시적 확장). 주입 콘텐츠에 원 출처 chunk id 태깅.
- **mastery 귀속**: weaving 블록의 채점 결과는 현재 절 개념이 아니라 **원래 약점 개념(origin concept_id)의 mastery를 갱신**. 블록에 origin concept_id 태깅 (kind=review 라우팅 재사용 가능).
- 오답노트는 누적 (스키마는 ISSUE-009와 함께 설계).

## 4. 구현 우선순위 (yoonhs-integration 기준)

1. **채점 견고성 + 레이트리밋** — 다른 모든 것의 전제. 인출이 평가 데이터가 되는 순간 오채점이 오답노트·복습·생성 전부에 누적 전파됨. (형식 오류 userInput 422 거부 포함 — 현재 조용한 오답 처리로 학습자 모델 오염 + 가짜 선행 삽입까지 실증됨)
2. **빠른 완료** (인출 2연속 통과 = 절 완료) + placement의 mastered/locked → 프라이어 전환
3. **사다리 배선** — localize 증거 기반화(§3-#1: `attempts>0` weak 조건) + cause 개입 시에만 노출, 선행 삽입 조건 좁히기·상한·빠른 통과
4. **오답노트 weaving** (스키마 + 생성 프롬프트 주입 + 귀속 규약)
5. **성향 프로브** (OAuth 병합 후, 3문항 샘플 선택형 + 스타일 파라미터)
