# 데모 시나리오 (초안)

> 화면으로 한 바퀴. 2026-08-09 기준 · 초안: 윤현석
> **리허설 전 문서다.** 시간은 대부분 실측이고, `?`는 아직 안 잰 것이다.

---

## 0. 이 문서가 푸는 문제

우리 파이프라인에는 **사람이 기다릴 수 없는 구간**이 있다.

```
파싱            수 분 (?)            ← 254KB PDF 기준. 정확히 안 쟀다
문항 생성        888초 (실측)         ← 15분. 절대 실시간 불가
진단 ⑥ 조달     과목당 몇 초 × N (?)
화면 생성        cold 5.5초 / prewarm 후 0.00초 (실측)
```

그래서 **무엇을 미리 만들어 두고 무엇을 그 자리에서 보여줄지**를 정해야 한다.
아무것도 안 정하면 심사 자리에서 로딩만 보여주게 된다.

---

## 1. 두 트랙으로 나눈다

| | 무엇 | 왜 |
| --- | --- | --- |
| **트랙 A** 실연 | 진짜 PDF를 그 자리에서 올린다 — **접수까지만** | "정말 되는구나"를 보여주는 건 이 30초다 |
| **트랙 B** 준비됨 | 이미 파싱된 수업으로 진단 → 학습 → 평가 → 분석 | 나머지 전부. 기다림 없이 흐른다 |

A에서 올린 자료는 발표가 끝날 때쯤 파싱이 끝나 있다. **마지막에 책장으로 돌아가
"아까 올린 게 지금 책이 됐습니다"로 닫으면** 트랙 둘이 하나로 이어진다.

## 2. 심사 전에 준비할 것

```bash
# ① 스택
docker compose up -d --build
docker compose exec backend uv run alembic upgrade head

# ② 시연용 수업이 준비돼 있는지
docker compose exec backend uv run python scripts/demo_seed.py --list

# ③ 없으면 만든다 — 자료 올리고 파싱이 끝난 뒤 수업으로 묶는다
#    (화면에서 /create 로 해도 되고, 그게 더 정직하다)

# ④ 누적을 채운다 — 분석 화면이 비면 "안 만든 기능"으로 읽힌다
docker compose exec backend uv run python scripts/demo_seed.py --doc <수업id> --sections 20

# ⑤ 문제은행 (15분) — 발표 한참 전에 걸어둘 것
curl -X POST "http://localhost:8000/api/courses/<수업id>/quiz/from-parsing/<문서id>" \
     -H "X-User-Id: 00000000-0000-0000-0000-000000000001"

# ⑥ 화면 미리 만들기 — 자료 개요를 한 번 열면 자동(prewarm)
```

체크리스트 — 발표 직전에 눈으로 확인:

```
[ ] /library     시연용 수업이 카드로 보인다
[ ] /analysis    막대 셋 이상이 차 있다
[ ] /quiz        과목 카드에 문항 수가 보인다   ← 15분 걸린 것
[ ] 학습 화면    클릭하면 즉시 열린다 (prewarm 됨)
[ ] 업로드용 PDF 작은 것 하나 준비 (되도록 10쪽 이하)
```

## 3. 흐름 (약 6분)

### ① 올린다 — 40초 · **실연**

```
/library → "새로운 학습 시작하기" → PDF 고름 → 목표 선택 → 생성
```

> "PDF를 올리면 접수증을 바로 받습니다. 파싱은 뒤에서 돌고, 끝나면 책장에
> 수업으로 꽂힙니다."

**여기서 기다리지 않는다.** 책장에 "수업 준비 중" 카드가 뜨는 것만 보여주고 넘어간다.

### ② 진단 — 90초 · **준비된 수업으로**

```
/library → 준비된 수업 → 진단하고 시작하기
```

- **① 왜 배우나** — 시험/실무/관심. 고르면 기한을 더 묻는다
- **② 분야 확인** — 자료를 읽고 판단한 값
- **③ 카드 4장** — 같은 개념을 비유·정의·표·왜 네 가지로. 읽기 편한 걸 고른다
- **④ 아는 것** — 과목으로 먼저, "들어봤다"만 펼쳐서 다시

> "시험이 아니라 **설정**입니다. 아는 건 설명을 줄이고 모르는 건 먼저 채웁니다."

⚠️ **③은 LLM 1콜이라 몇 초 걸린다.** 미리 한 번 열어두면 캐시된다.
⚠️ **⑤·⑥(확인 문항·조달)은 시간이 든다.** 리허설에서 재보고, 길면 진단을
   미리 끝내 두고 **결과 화면부터** 보여준다(목차가 길어진 것).

### ③ 진단이 목차를 바꿨다 — 30초 · **여기가 첫 번째 핵심**

```
/curriculum/<수업>
```

```
진단 전   목차  4 · 화면 47
진단 후   목차 14 · 화면 60     ← 앞에 보강 단원이 붙었다
```

> "모른다고 한 과목은 **교재에 없어도** 앞에 단원으로 넣습니다. 진단이 점수가
> 아니라 목차를 바꾸는 겁니다."

🔴 지금은 보강이 10개나 붙어서 교재 내용이 11번째로 밀린다(§5 참고).
   **시연 전에 이게 정리돼 있어야 이 장면이 산다.**

### ④ 학습 화면 — 90초 · **두 번째 핵심**

```
목차 하나 → 화면 하나
```

- 설명이 나오고 (성향에 맞춘 분량·형식)
- **📎 교재 원문**을 펼치면 요약이 아니라 그 문장 그대로
- 바로 아래 **꺼내보기** — 빈칸을 채운다
- 틀리면 그 개념이 다음 설명에 엮인다

> "읽기만 하면 안 남습니다. 읽고 **바로 꺼내게** 합니다."

### ⑤ 단원 평가 — 40초

```
목차 → 단원 평가
```

> "화면 안에서 묻는 것과 다릅니다. **화면을 가로질러** 헷갈리는 지점을 찾습니다."

⚠️ 진도 60%를 넘겨야 열린다. **작은 수업으로 시연하거나** 시드로 미리 진도를 채운다.

### ⑥ 복습 — 30초

```
🔁 복습 → 며칠 뒤로 이동
```

> "망각곡선으로 다시 꺼낼 때를 정합니다. 시연이라 시계를 옮기겠습니다."

`?days=N`이 화면에 있으니 그 자리에서 14일 뒤를 보여줄 수 있다.

### ⑦ 메타인지 분석 — 60초 · **세 번째 핵심**

```
/analysis
```

> "여기가 다른 점입니다. 진단·학습·복습·평가가 **각각 다른 무게로** 하나의
> 준비도에 모입니다. 준비도 = 이해도 × 진도 × 회상이고, 하나라도 0이면
> 준비된 게 아닙니다."

- 출처별 막대와 가중치(×0.5 ~ ×2.0)
- 자주 걸리는 개념
- 자료별 준비도

⚠️ **막대가 하나만 서 있으면 이 장면이 죽는다.** 시드를 꼭 돌려둘 것.

### ⑧ 문제집 — 40초

```
/quiz → 과목 → 범위 → 풀이 → 채점
```

> "학습과 **분리된** 문제은행입니다. 풀이 기록은 학습 숙련도에 안 섞입니다."

채점하면 정답·해설과 함께 **근거 원문(교재 몇 쪽)**이 나온다 — 여기가 포인트.

### ⑨ 닫기 — 20초 · **트랙 A와 만난다**

```
/library
```

> "처음에 올린 자료가 그동안 파싱이 끝나 수업이 됐습니다."

## 4. 말할 거리 — 숫자로 뒷받침되는 것만

```
파싱      개념 근거 부착률 100% · 미배정 조각 0        (실측 probe.pdf)
학습      화면 43개 · 원문 없는 화면 0
문제      저장 158 / 폐기 200 — 검증에서 반이 떨어진다  (QUIZ_TUNING §12.7)
          "많이 만드는 게 아니라 **틀린 걸 안 내보내는** 게 어렵습니다"
누적      네 출처 · 가중 0.5~2.0 · 준비도 = 이해도 × 진도 × 회상
```

## 5. 🔴 시연 전에 정리돼야 하는 것

| | 무엇 | 누구 |
| --- | --- | --- |
| 1 | **보강 단원 과다** — "안다"고 한 과목까지 10개 전부 생성, 이름 중복(`컴퓨터 기본`/`컴퓨터 기초`). 교재가 11번째로 밀린다 | 박지성 |
| 2 | **교재 활용 41%** — 붙어야 할 화면 73곳 중 30곳 | 박지성 |
| 3 | 진단 ⑤·⑥ 소요 시간 미측정 — 길면 시나리오에서 뺀다 | 리허설 |
| 4 | 파싱 소요 시간 미측정 — ①의 "발표 끝에 완성" 타이밍이 여기 걸린다 | 리허설 |
