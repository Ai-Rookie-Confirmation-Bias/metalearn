# 데모 시나리오 — **3분 영상**

> 2026-08-10 · 윤현석. 촬영·편집용 **컷 대본**이다.
> 기다릴 수 없는 구간(파싱 수 분 · 문항 생성 888초 · 진단 조달)은 **전부 사전 준비**.
> 화면에서 실연하는 건 이미 만들어진 상태를 **보여주는 것**뿐이다.

---

## 0. 이 3분이 증명하는 것 하나

> **"같은 PDF인데, 진단에서 답한 것에 따라 다른 수업이 됩니다.
> 그리고 읽고 꺼낸 기록이 하나의 준비도로 모입니다."**

기능을 나열하지 않는다. **A/B 두 화면을 나란히 놓는 것**이 이 영상의 심장이고,
나머지는 그게 진짜라는 걸 받쳐 준다.

| # | 장면 | 시간 | 핵심 |
|---|---|---|---|
| ① | 파이프라인은 **말로** | 0:00–0:40 | 화면 정지 + 내레이션 |
| ② | ★ **A/B — 같은 책, 다른 사람** | 0:40–1:40 | 분할 화면 |
| ③ | 읽고 **바로 꺼낸다** | 1:40–2:20 | 그림 · 📎원문 · 빈칸 |
| ④ | 하나의 준비도 · 근거 있는 문제 | 2:20–3:00 | `/analysis` → `/quiz` |

## 1. 촬영에 쓸 실제 값

> ⚠️ **아래 UUID는 2026-08-10에 만든 것이다. 새 PDF로 다시 만들면 전부 바뀐다.**
> 바뀌는 것과 안 바뀌는 것을 갈라 두니, 새로 만들 땐 §3부터 읽고 여기 값만
> 교체하면 된다.
>
> ```
> 바뀐다      코스 UUID · 화면 id · 글자 수 · 인용문 · 그림 수 · 문항 수
> 안 바뀐다   A/B를 만드는 방법 · 목차 배지 문구 · 비유 유무 · 컷 순서와 내레이션
> ```
>
> 컷 대본(§2)은 그대로 쓸 수 있다. 자막 숫자만 당일 값으로 바꿔라.

두 수업은 **같은 PDF 2개**(ch01 데이터통신 개요 + ch02 OSI 참조모델)로 만들었고,
**진단 답만 반대**다.

```
A  시험 준비 · 2주 · 비유로     c959cdcc-d3bc-4b81-af3a-c7ee596f4691   목차 0·1·2 compressed
B  실무에 쓰려고 · 정의부터      3f29e2b0-717f-4b59-9759-33c8dfe96e74   목차 0·1·2 deep
```

> ⚠️ **목차 3(프로토콜 기본 개념)은 A·B 둘 다 `normal`이다. 촬영에 쓰지 마라.**
> 거기에만 학습 기록을 넣어 뒀는데, **측정이 있으면 측정이 진단을 이긴다** —
> 배운 목차의 분량은 "무엇을 하려는가"가 아니라 그 사람이 실제로 맞힌
> 비율이 정한다. 설계대로지만 A/B 대비는 사라진다.
>
> 그래서 시드를 뒤로 뺐다(`--from-chapter 3`). 앞에서부터 채우면 목차 0이
> 측정 기반이 되어 **첫 화면에서 A와 B가 똑같아 보인다** — 한 번 그렇게 찍었다.
>
> **A와 B는 화면 id가 같아 진도도 공유한다.** 한쪽에 학습을 넣으면 다른
> 쪽에도 그대로 보인다. 두 사람인 척 진도까지 갈라 보이려 하지 마라.

**화면 id는 A·B가 같다.** URL에서 코스 UUID만 바뀐다 — 분할 화면을 만들 때
같은 위치·같은 스크롤로 맞출 수 있다.

```
비교할 화면   1e9180adf3b3   "데이터 통신"        그림 2장   ← ②③에 쓴다
대안          5fe2377821a6   "프로토콜"           그림 3장
              8b530e49b317   "데이터 전송계"      그림 3장 (목차1)

A  http://localhost:5173/curriculum/c959cdcc-d3bc-4b81-af3a-c7ee596f4691/sections/1e9180adf3b3
B  http://localhost:5173/curriculum/3f29e2b0-717f-4b59-9759-33c8dfe96e74/sections/1e9180adf3b3
```

실측 (같은 화면, 2026-08-10):

```
        분량(목표)              형식(성향)
A       323자 · 문항 4          비유 블록 있음 — "우체국에서 편지를 보내는 것과 비슷하다"
B       827자 · 문항 5          비유 없음 · 정의와 구조로

                       같은 화면 · 같은 그림 2장 · 같은 원문 717자
목차 화면 문구
A   "시험이 2주 남아 핵심만 보여드립니다."
B   "실무에 쓰시려는 자료라 왜 그런지까지 함께 씁니다."
```

**축이 둘이라는 게 이 데모의 요점이다.** 진단에서 물은 것도 둘이었다 —
"왜 배우는가"(분량)와 "어떤 설명이 편한가"(형식). 하나만 보여주면 심사에서
"글자 수만 다르네"로 읽힌다.

> 서버를 재시작하면 레슨 캐시가 비어 첫 열람에 5~7초가 걸리고 **문장이
> 다시 생성된다.** 위 인용문과 글자 수는 그때 바뀐다(실측 2.5~2.9배 사이에서
> 흔들렸다). 비유가 **있고 없고**는 유지된다 — 그쪽이 지시로 고정돼 있다.
> 촬영 직전에 두 URL을 한 번씩 열어 두면 본 촬영은 즉시 뜨고, 그때 본 문장을
> 그대로 쓰면 된다.

## 2. 컷 대본

내레이션은 **읽을 문장 그대로**다. 괄호는 읽지 않는다.
컷마다 (초)는 목표 길이 — 합계 약 2:50, 전환 여백 10초.

### ① 0:00–0:40 · 파이프라인은 말로

> ⚠️ **여기서 아무것도 실연하지 않는다.** 파싱은 분 단위고 진단은 6단계다.
> 3분에 넣으면 ②가 죽는다. 책장을 띄워 놓고 말로 설명한다.

```
컷1  6초   [책장 /library] 전체가 보이게. 커서 없음
          "PDF를 올리면 파싱이 목차와 개념, 그림을 뽑아냅니다."

컷2  8초   [책장] 수업 카드 하나에 커서를 천천히
          "그 다음 진단이 왜 배우는지, 어떤 설명이 편한지,
           무엇을 이미 아는지를 묻습니다."

컷3  10초  [클릭] 수업 열기 → 목차 사이드바에서 정지
          "모른다고 한 과목은 교재에 없어도 목차 앞에 채워 넣습니다.
           시험이 아니라 설정입니다 — 점수가 아니라 배울 순서가 바뀝니다."

컷4  8초   [정지] 사이드바 ✚ 배지 / "교재 밖" 한 곳 확대
          (말 없음 — 배지를 읽을 시간)

컷5  8초   [정지] 책장으로 복귀
          "여기까지는 몇 분이 걸립니다. 그래서 미리 돌려 두고,
           지금부터는 만들어진 뒤를 보여드립니다."
```

### ② 0:40–1:40 · ★ A/B — 같은 책, 다른 사람

> **편집: 화면을 좌우로 분할한다.** 왼쪽 A, 오른쪽 B. 같은 순간에 같은 스크롤.
> 촬영은 두 번 따로 하고 편집에서 붙인다 — 동시 조작은 불가능하다.

```
컷6  10초  [분할] 좌 A 목차 화면 · 우 B 목차 화면 (같은 목차 0)
          "같은 PDF입니다. 진단에서 고른 목표만 다릅니다."

컷7  10초  [분할·확대] 좌우의 분량 배지와 이유 문구
          좌 "시험이 2주 남아 핵심만 보여드립니다."
          우 "실무에 쓰시려는 자료라 왜 그런지까지 함께 씁니다."
          "시험이 2주 남으면 핵심만 짧게,
           실무면 구조와 이유까지 길게 씁니다."

컷8  14초  [분할] 같은 화면 "데이터 통신"을 좌우에서 열고 설명을 나란히 스크롤
          (말 없음 — 글 길이 차이가 눈에 보이게)

          ※ 열자마자 **왼쪽 맨 위에만 노란 💡 카드**가 있다. 설명 문단보다
            위에 온다 — 스크롤 없이 첫 화면에서 이미 갈린다. 컷9가 이걸 쓴다.

컷9  10초  [분할·확대] **좌측 상단의 노란 💡 비유 카드**로 커서 → 우측 같은 자리(없음)
          "왼쪽은 비유로 설명해 달라고 했고, 오른쪽은 정의부터 달라고 했습니다.
           왼쪽에만 우체국 비유가 붙습니다."

          ⚠️ 좌우 **첫 문장은 거의 같다.** 정의를 바꾸지는 않기 때문이다 —
             "왼쪽은 예시로 시작한다"고 말하지 마라. 갈리는 건 비유 블록의
             유무와 그 뒤 분량이다.

컷10 8초   [분할 해제] 좌우 글자 수를 자막으로 — 323자 / 827자
          "바뀐 건 두 가지입니다. 얼마나 쓸지, 그리고 어떻게 쓸지."

          ※ 글자 수는 재생성마다 흔들린다. **촬영 당일 화면의 실제 값**을
            자막에 넣어라(§1).
```

### ③ 1:40–2:20 · 읽고 바로 꺼낸다

> A 화면(왼쪽에 쓰던 것) 하나로 계속 간다. 화면을 새로 열지 않는다.

```
컷11 8초   [A 화면] 설명 아래로 스크롤 → 교재 그림 2장이 들어옴
          "설명 아래에는 교재에 있던 그림이 그대로 붙습니다."

컷12 10초  [클릭] 📎 교재 원문 펼치기 → 원문이 열리는 것까지
          "요약이 아닙니다. 이 책의 문장 그대로입니다.
           AI가 지어낸 해설이 아니라는 근거입니다."

컷13 14초  [스크롤] 개념별 빈칸 → 하나에 답 입력 → 확인
          "그리고 바로 꺼내게 합니다. 개념마다 물어봅니다.
           읽기만 하면 남지 않으니까요."

컷14 6초   [정지] 채점 결과(정답/오답 표시)
          (말 없음)
```

### ④ 2:20–3:00 · 하나의 준비도 · 근거 있는 문제

```
컷15 14초  [탭 이동 /analysis] 진단 카드 → 출처 막대 순서로 커서
          "진단은 배울 순서를 정했고, 그 뒤에 읽고 다시 꺼내고 평가한 기록이
           무게를 달리해서 하나의 준비도로 모입니다."

컷16 6초   [스크롤] "자주 걸리는 개념"
          "여기서 걸린 개념은 다음 설명에 다시 나옵니다."

컷17 12초  [탭 이동 /quiz] 과목 → 범위 → 1문항 → 답 선택 → 제출
          "학습과 섞이지 않는 문제은행도 있습니다.
           바로 문제부터 풀고 싶은 사람을 위한 자리입니다."

          ★ **문항이 실제로 있는 수업을 골라라.** 문제은행은 수업마다 따로
            만들고, 만든 적 없는 수업은 0문항이다(2026-08-10 기준 "데이터 통신"
            114문항 / A·B는 0). 별개 기능이라고 소개하는 컷이라 ②③에서 쓴
            수업과 달라도 흐름은 어색하지 않다.
            어느 수업에도 문항이 없으면 **이 컷을 뺀다** — 888초짜리를 촬영
            당일에 시작하지 마라(§3 시간 예산).

컷18 8초   [정지·확대] 채점 결과의 근거 원문 + "교재 5쪽"
          "채점하면 정답만이 아니라 교재 몇 쪽인지가 같이 나옵니다."
```

## 3. 촬영 준비

### 시간 예산 — **기다리는 것부터 먼저 걸어라**

새 PDF로 처음부터 만들 때 드는 시간이다. 순서를 틀리면 촬영을 기다리며 앉아 있게 된다.

```
파싱               자료당 수 분          ← 제일 먼저. 이게 끝나야 나머지가 시작된다
진단 6단계         수업당 2~3분          A와 B, 두 번 (답만 반대로)
문제은행           888초 = 약 15분/자료  ← ④에 쓸 거면 **전날 걸어 둔다**
누적 시드          화면 13개에 ~95초
prewarm            화면당 5~7초 (병렬)
```

> 촬영 당일에 파싱과 문제은행을 동시에 시작하지 마라. 문제은행은 안 써도
> ④의 앞부분(`/analysis`)은 살아 있다 — §5 대비표 참고.

### 발표 전날

```bash
docker compose up -d --build
docker compose exec backend uv run alembic upgrade head
```

**A/B 수업 만들기** — 같은 문서 두 개로 코스를 둘 만들고 진단만 반대로 준다.
화면에서 하면 되고, 이미 만들어 둔 두 수업(§1)을 그대로 써도 된다.

```
A   목표 시험 준비 · 기한 2주 · 형식 비유로   · 선수는 전부 "안다"
B   목표 실무에 쓰려고 · 형식 정의부터        · 선수는 전부 "안다"
```

> ⚠️ **선수를 "안다"로 통일하는 이유** — "모른다"를 고르면 보강 단원이 생기고,
> 지금은 고른 개수만큼(최대 10개) 붙어서 **교재 목차가 화면 아래로 밀린다.**
> ①에서 ✚ 배지를 보여줄 땐 보강이 있는 다른 수업을 쓰고, ②의 A/B는 보강 없이
> 분량·형식 차이만 남기는 쪽이 깨끗하다.

**책장 비우기** — 파일 픽스처는 DB 행이 없어 **누구 책장에나** 뜬다. 촬영할
땐 시연 수업 셋에 픽스처 셋이 섞여 일곱 권이 됐다.

```bash
echo 'CURRICULUM_FIXTURES_OFF=1' >> backend/.env
docker compose up -d backend
```

> ⚠️ `CURRICULUM_FIXTURES`(끝에 `_OFF` 없는 것)에 값을 넣지 마라. 그건
> **픽스처 디렉터리 경로**다 — 거기에 `off`를 넣으면 경로가 `off`가 되어
> 픽스처를 읽는 테스트가 전부 죽는다. 한 번 그렇게 했다.
>
> `restart`가 아니라 `up -d`다. `restart`는 `env_file`을 다시 안 읽는다 —
> 이걸로도 한 번 헤맸다.

**누적 채우기** (④ 분석 막대)

```bash
docker compose exec backend uv run python scripts/demo_seed.py \
  --doc <A수업id> --from-chapter 3 --sections 13 --wrong 0.45
```

> `--from-chapter 3`이 핵심이다. 빼면 목차 0이 측정 기반으로 넘어가
> **②에서 A와 B가 똑같아 보인다**(§1 경고). 마지막 목차 번호를 넣으면 된다.
>
> `--wrong 0.45`도 그냥 넣은 값이 아니다. **약점은 같은 개념을 2회 이상
> 틀려야 잡힌다**(`WEAK_THRESHOLD`). 기본값 0.25로 돌렸더니 화면마다 1개씩만
> 틀려서 **컷16의 "자주 걸리는 개념"이 텅 비었다**(실측 약점 0개).
>
> 돌린 뒤 확인 — 여기가 비면 컷16을 빼야 한다:
>
> ```bash
> curl -s http://localhost:8000/api/curriculum/analysis \
>   -H "X-User-Id: 00000000-0000-0000-0000-000000000001" | grep -o '"weakConcepts":[^]]*]'
> ```

**문제은행** (④ 문제 풀이) — **안 돌려도 된다.** "데이터 통신" 수업에 이미
114문항이 있다(2026-08-10 확인). 컷17은 그 수업으로 찍는다.

확인만:

```bash
docker compose exec -T db psql -U postgres -d metalearn_v3 \
  -c "select c.title, count(q.id) from courses c left join quiz_items q on q.course_id=c.id group by c.title;"
```

굳이 A 수업에도 만들려면 — **실측 888초, 두 문서면 그 두 배다.** 촬영
당일에 시작하지 마라.

```bash
curl -X POST "http://localhost:8000/api/courses/<A수업id>/quiz/from-parsing/<문서id>" \
     -H "X-User-Id: 00000000-0000-0000-0000-000000000001"
# 상태: GET 같은 경로 + /status  → done 이면 준비 완료
```

**화면 미리 만들기** — A와 B의 자료 개요를 각각 한 번 열면 prewarm이 돈다.
②에서 쓸 화면(`1e9180adf3b3`)은 **양쪽 다 한 번씩 열어 둔다.**

## 6. 말하지 말 것

- 파싱 단계 수, alembic, 브랜치 이름, 저장률·폐기 수
- **"러닝 스타일 맞춤"** — ②는 *읽기 편한 형식*을 고른 것이지 학습 효과 주장이
  아니다(Pashler 2008에서 반증됨). "맞춤 학습법"이라고 하면 틀린 말이 된다
- **"AI가 교재 밖 내용을 어디서 가져온다"** — 가져오는 게 아니라 **AI가 쓴다.**
  물으면 그대로 답한다: "선수 개념은 모델이 씁니다. 그래서 그 단원엔 📎 원문이
  안 붙고, 화면에 '교재 밖'이라고 표시합니다"
- 로그인/OAuth — 시연에 안 쓴다

## 부록 · 6분으로 늘릴 때

새 주제를 만들지 않고 이 순서로만 끼운다.

1. 진단 화면 ①②③만 짧게 (목표·분야·카드 4장) — ⑤⑥ 조달은 여전히 사전 완료
2. 보강 단원이 붙은 수업으로 ✚ 목차를 더 보여주기
3. 단원 평가 한 문항
4. 복습 `?days=14` 시계 이동
5. 업로드 접수(`/create`)까지 — **완료는 약속하지 않는다**
