## 2. 새 API 2개

### 개념 검색 — `GET /api/parsing/concepts/search`

개념을 **뜻으로** 찾는다. 문서 경계를 넘는다.

| 파라미터 | 기본 | 설명 |
| --- | --- | --- |
| `q` | (필수) | 찾을 개념 이름이나 설명 |
| `limit` | 10 | 1~50 |
| `min_sim` | 0.0 | 이 유사도 미만은 버린다 |
| `document_id` | 전체 | 여러 번 주면 그 자료들 안에서만 |

```bash
curl "http://localhost:8000/api/parsing/concepts/search?q=cocomo&limit=5"
curl "http://localhost:8000/api/parsing/concepts/search?q=소프트웨어%20비용%20산정"
curl "http://localhost:8000/api/parsing/concepts/search?q=cocomo&document_id=<uuid>"
```

```json
[
  {
    "id": "…", "name": "COCOMO 모형",
    "definition": "보헴이 제안한 LOC 기반 소프트웨어 비용 산정 기법",
    "source": "book", "global_key": "cocomo-model",
    "similarity": 0.579,
    "document_id": "…", "filename": "pilgi.pdf",
    "topic_title": "5. 정보시스템 구축 관리",
    "evidence": [ { "segment_seq": 13, "sentence_seq": 18,
                    "char_start": 472, "char_end": 532,
                    "text": "보헴(Boehm)이 제안한 것으로, 원시 프로그램의 규모(LOC)에 의한 …",
                    "page_from": 34, "page_to": 37 } ]
  }
]
```

**이름이 안 겹쳐도 찾는 게 요점이다.** 실측: `소프트웨어 비용 산정`으로 검색하면
그 말이 이름에 없는 `Cost Estimation`(0.723) · `COCOMO 모형`이 올라온다.

주의 두 가지:

- **한글로 약어를 치면 약해진다.** `cocomo` 0.579 vs `코코모` 0.421. 영문 약어는
  영문으로 검색하는 편이 정확하다.
- 검색어는 내부에서 **query 모델**로 임베딩한다. 개념 벡터가 query 모델로
  만들어져 있어서다 — passage로 넣으면 실측에서 0.579 → 0.399로 떨어졌다.
  (조각 본문을 찾을 때는 반대로 passage다.)

### 근거 위치 — `GET /api/parsing/documents/{id}/tree`

기존 트리 응답의 개념에 `evidence`와 `global_key`가 추가됐다.

```json
{
  "id": "…", "name": "모듈",
  "definition": "모듈화를 통해 분리된 시스템 기능 단위로, 단독 컴파일 및 재사용이 가능함",
  "source": "book", "global_key": "module",
  "segment_seqs": [1],
  "prerequisite_ids": ["…"],
  "evidence": [
    { "segment_seq": 1, "sentence_seq": 88,
      "char_start": 2433, "char_end": 2462,
      "text": "- •모듈화를 통해 분리된 시스템의 각 기능들이다.",
      "page_from": 4, "page_to": 6 }
  ]
}
```

**좌표계는 조각 기준이다.** `char_start`/`char_end`는 그 조각 `content` 안의
offset이라 정확하다. 반면 페이지는 **조각의 범위**(`page_from`~`page_to`)이고
문장 하나의 정확한 페이지가 아니다 — 조각이 여러 페이지에 걸치기 때문이다
(실측: 조각 1 = p.4~6). 화면은 조각 본문을 통째로 받아 이 구간만 강조하면
원문 대조가 정확히 맞는다.

근거 부착률은 실측 99%(개념 397개 중 394개)다. 빈 배열은 두 경우다 —
LLM이 근거를 특정하지 못했거나, 원문에 없는 선수개념(끊긴 고리)이라 근거가
있을 수 없거나.

**근거 문장이 항상 정확하지는 않다.** 3개 중 1~2개는 개념을 정확히 짚고
나머지는 인접 문장을 함께 집는 수준이다. 위치를 짚어주는 용도로는 쓸 만하고,
"이 문장만 딱 보여준다"에는 검증이 한 겹 더 필요하다.

### 코스를 시작하기 전에 필요한 것 — `GET /api/courses/{id}/prereqs`

12.5가 뽑은 선수 후보를 **이 코스의 실제 자료들과 대조해** 거른 결과다.
첫 호출에서 계산·저장하고 이후는 조회뿐이다.

```bash
curl "http://localhost:8000/api/courses/{id}/prereqs"
curl "http://localhost:8000/api/courses/{id}/prereqs?status=pass,gray"  # 화면용
curl "http://localhost:8000/api/courses/{id}/prereqs?refresh=true"      # 자료 바꿨을 때
```

```json
[ { "subject": "리눅스 기초", "item": "SSH를 통한 원격 접속",
    "why": "EC2 인스턴스 운영 이해를 위해",
    "seq": 1, "ordered": false,
    "status": "pass", "similarity": 0.428, "rejected_by": "라우팅",
    "known": null } ]
```

`status`가 셋인 이유가 중요하다.

| | 뜻 | 화면 |
| --- | --- | --- |
| `pass` | 확실히 책 밖 | 그냥 보여준다 |
| `gray` | 자료에 조금 나온다 | 보여주되 "△ 자료에 조금 나옴" 표시 |
| `rejected` | 자료가 확실히 가르친다(유사도 0.75↑) | 숨긴다 |

**`gray`를 숨기지 않는 게 설계다.** LLM 판정이 실행마다 뒤집혀서
(`라우팅 원리`가 한 번은 통과, 한 번은 기각) 판정으로 항목을 지우게 두지
않았다. 항목 하나가 더 뜨는 건 훑으면 되지만, 안 뜬 항목은 물어볼 기회 자체가
사라진다. `rejected`는 임베딩 0.75 이상만 — `CIDR 표기법`(0.783)처럼
흔들리지 않는 것들이다.

`known`은 24번 진단이 채운다(`known|heard|unknown`). 지금은 항상 NULL이다.

### 뼈대 목차 + 본문 설명 — `GET /api/courses/{id}/tree`

18번의 산출물이자 이 서비스가 하려는 것의 본체다. **PPT 순서로 가되 설명은
교재에서** 온다.

```bash
curl "http://localhost:8000/api/courses/{id}/tree"
```

```json
{ "course_id": "…", "title": "정보처리기사",
  "skeleton_document_id": "…", "body_document_ids": ["…"],
  "linked_concepts": 120, "total_concepts": 452,
  "topics": [
    { "seq": 0, "title": "1. 소프트웨어 설계", "origin": "book", "plan": "normal",
      "concepts": [
        { "name": "도커", "definition": "…",
          "evidence": [ { "segment_seq": 2, "sentence_seq": 41,
                          "char_start": 1180, "char_end": 1237, "text": "…",
                          "page_from": 6, "page_to": 9 } ],
          "body": [ { "name": "Docker", "filename": "실기요약노트.pdf",
                      "similarity": 0.9841, "kind": "same", "verified_by": "embed",
                      "definition": "…",
                      "segments": [ { "seq": 14, "content": "…",
                                      "page_from": 51, "page_to": 53 } ] } ] } ] } ] }
```

- **목차는 `course_topics`다** — 사용자가 고친 복사본이지 원본이 아니다
- `evidence`는 **뼈대 자료** 안에서의 근거 위치
- `body`는 **다른 자료**가 그 개념을 설명하는 곳. 조각 본문이 통째로 온다
- `kind=related`면 상위·하위 개념이라 설명이 조금 넓거나 좁을 수 있다
- 연결은 **문서쌍 단위로 저장**된다. 실측: 첫 호출 3.9초 → 두 번째 0.31초.
  같은 두 책을 쓰는 다음 사람은 계산이 없다

## 4. 문턱값 — 전부 실측이다

지어낸 숫자를 한곳에 모은다. 구현 중 상수를 새로 만들면 여기에 줄을 추가한다.

| 값 | 어디 | 어떻게 쟀나 |
| --- | --- | --- |
| **0.75 / 0.50** | 16' 기각·회색 | 21개 정답 케이스. 책 안 최소 0.509 / 책 밖 최대 0.468 |
| **0.85 / 0.75 / 0.70** | 18 연결 | pilgi 452개를 ryan 578개에 전부 대조 |

| 2회 | 분야 판정 호출 | 회수율용. 재현성이 아니다 (§5) |

### 18단계 연결 회귀 (pilgi 뼈대 + ryan 본문, 14/14)

```
안 붙어야 함   MD4 ✓   블루스나프 ✓   블루프린팅 ✓   Project 연산자 ✓
              자료구조 ✓   스택 ✓   do~while문 ✓
붙어야 함      도커→Docker 0.984 ✓        트랜잭션→트랜잭션 0.976 ✓
              SOLID 원칙 0.951 ✓         함수적 종속 0.922 ✓
              버블 정렬 0.910 ✓           분산 데이터베이스 0.913 ✓
              정규화→정규화 0.740 ✓  ← 회색지대, LLM이 살림
```

`정규화`(0.740)와 `블루스나프`(0.72)가 같은 구간에 있었는데 정확히 갈렸다.
이게 회색지대에 LLM을 넣은 이유다 — 이름만 닮은 딴것은 임베딩으로 못 가른다.

실측 결과: 452개 중 **120개(27%)**에 교재 설명이 붙었다.
연결 118쌍 = same/embed 34 · related/embed 66 · same/llm 18.

## 5. 알려진 한계

- **목차 품질** — 얇은 자료는 조각 예산을 줄여 목차 재료를 확보하지만
  (network 4조각 → 15조각), 43슬라이드에 단원 3개는 성길 수 있다.
  슬라이드 제목이 조각 heading으로 남아 있어 2단 목차로 확장할 재료는 된다.
- **density 문턱 800자/페이지** — 표본 3권 기준이다. 뼈대 최댓값 321과 본문
  최솟값 1,266 사이가 넓어 위치를 더 재봐야 한다.
- **끊긴 고리는 결손 판정에 못 쓴다 (16번 폐기)** — pilgi의 55개를 전부 봤더니
  `행동 패턴`(11회)·`릴레이션`(5)·`데이터베이스`(3)·`변수`·`제어문`처럼 **그 책이
  가르치는 내용**이 대부분이었다. 목차에 "3. 데이터베이스 구축"이 있는데
  `데이터베이스`가 끊긴 고리로 잡히는 식이다. 개념↔조각 연결이 누락돼 끊긴 것처럼
  보였을 뿐이고, `insertion-sort` 같은 영문 슬러그가 한글 개념과 중복으로 섞여
  있기도 하다. 그리고 근본적으로 **책이 언급조차 안 한 선수는 원문에서 나올 수가
  없다.** 그래서 방향을 뒤집어 12.5단계(위→아래 분야 판정)로 대체했다.
  `GET /courses/{id}/gaps`는 참고용으로 남겨 뒀다.
- **분야 판정은 재현되지 않는다** — 같은 자료를 두 번 물으면 개수부터 다르다
  (pilgi 6개 vs 2개). 교집합으로 거르려 했으나 과목 이름은 임베딩으로 못
  가른다는 게 실측으로 확인됐다 — `AWS 기본 개념`↔`AWS 기본 서비스`(같음, 0.806)
  와 `네트워크 보안 기초`↔`네트워크 기초`(다름, 0.866)가 겹친다. 그래서 2회
  **합집합**을 취하고 거르는 일은 뒤의 기각 검사에 맡긴다. 놓치면 복구가 안 되고
  (교집합으로 돌렸을 때 network의 `Linux 기초`가 사라졌다) 헛것은 뒤에서 걸린다.
- **회색지대 LLM 판정이 흔들린다** — 16'에서 `라우팅 원리`가 실행마다 통과와
  기각을 오갔다. 그래서 LLM이 항목을 **지우지 못하게** 했다(gray로만 표시).
  최종 확인은 24번 사용자 확인 화면이 한다.
